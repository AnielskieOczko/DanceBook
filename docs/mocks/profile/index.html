Avatar menu and profile page

Issue #217, part of #201. First the avatar dropdown, then three directions for the reworked profile page. All keep the full domain detail: training stats and streak, badges (#39), counts of Notes, choreographies and figures, calendars with the default one, language, medal badge style, password, assistant preferences and recent activity. Everything below is clickable. Nothing here is built yet.

1. Avatar dropdown

One menu on every width: Profile, Language (expands in place, applies immediately, no trip to the profile page), Log out. Today desktop has no menu (the avatar links straight to the profile) and the phone menu mixes navigation with profile items. Keeping the phone-only shortcuts (Choreographies, Collections, Admin) in a top group, because the bottom bar only fits four tabs. Open it, press Escape, or click outside to close.

Header block
Name and role so the menu says whose session this is. Not a link.
Language row
Shows the current value on the right. Choosing one posts to the existing /profile/locale and reloads. "Browser default" stays an option.
Log out
Separated and red, last, a POST form as today. Moves out of the profile page foot in every direction below.

Recommendation: Direction C Recommended

Summary plus settings list fits this app best. Most visits are on a phone, where the hero keeps the streak and the Note, choreography and figure counts in the first screen and settings collapse to one line each with their current value. Badges, calendars, language, badge style, assistant and password all keep their place. It reuses existing pieces (cards, selects, forms), needs no routing for tabs, and the page stays one scroll. Take A's training chart and week bars into the hero later if the stats should carry more weight.

Runner-up: B Tabs, if Preferences and Security will keep growing. Least suited: A, which is long on a phone and makes settings an afterthought.

2. Direction A: Dashboard

One scrolling page, read-first. Identity and the numbers that matter (streak, hours, sessions) on top, then achievements and activity on the left, library counts and calendars on the right, with the settings as a quiet block at the bottom. Best when the page is mostly looked at. Everything is visible, so it is long on the phone.

3. Direction B: Tabs

Identity header stays put; Overview (stats, badges, counts, activity), Calendars, Preferences (language, badge style, assistant) and Security (password). Shorter screens, one concern at a time, deep-linkable per tab. Costs an extra tap to reach settings, and stats are hidden when you are on another tab.

4. Direction C: Summary plus settings list Recommended

A compact hero with the streak and counts, badges below, then settings as an accordion list where each row shows its current value (Language: English, Default calendar: Dance Training) and expands in place. On desktop the hero sits in a left column beside the list. The best phone experience and the least scrolling, but the density of the training stats is lower than A.

Decisions for review

Which direction?
A for the stats-first view, B for the cleanest structure, C for phone-first. Elements can be mixed, for example B's tabs with C's accordion inside Preferences.
Language in two places
The dropdown is the quick switch; the profile keeps the full Preferences entry. Both write the same preference.
Assistant preferences
Shown as example switches (suggest figures, remember history, open full window). Final list to be confirmed against #201.
Data shown
All numbers and names are sample data. The current page's "Library 124" and "Styles 12" placeholders are replaced with real counts.
