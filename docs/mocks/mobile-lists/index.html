Mobile Notes and Figures lists

Three directions for the phone layout of the two list pages (375 px wide). Each option uses the same pattern on both lists, so Notes and Figures read as one product. Every option keeps the domain detail from the desktop table: figure style, class letter, medal and syllabus-steps flag; note style, category, rating, privacy and date.

Shared across all three: pill search and filter controls (#356), pill badges (#358), no Source column (#359), a "show more" footer that stands for the pagination of #357, and the sticky toolbar. Where row actions (edit, delete) live is decided by the actions mock (#361); each option shows a placeholder for it.

A · Compact rows with a filter sheet star Recommended

Density. Four to five rows above the fold per screen. Hairline dividers, no cards, in line with the reference-manual direction.

Scales. Row height is fixed, so paging, "show more" and long catalogs stay predictable.

Filters. One search pill plus one Filters button. The full filter set opens in a bottom sheet; active filters stay visible as removable chips.

Cost. Less visual weight per item, so Notes lose some of the "card" feel they have today.

B · Cards with a quick-filter chip row

Scannable. Each item is a rounded card with its detail as chips; closest to today's Notes mobile card.

Filters. A scrolling row of style chips under the search gives one-tap filtering; the rest sits in a sheet.

Cost. Roughly 2.5 cards per screen, and repeated bordered cards are the pattern the project moved away from. Long lists get tiring to scroll.

C · Rows grouped under sticky style headers

Fits the syllabus. The catalog is naturally organised by dance style, so headers double as navigation, with a jump rail on the right.

Densest. Single-line rows, so many figures fit on screen.

Cost. Works for Figures (default sort is style then name) but Notes are sorted by date, so grouping breaks as soon as the sort changes. It also limits the detail per row to one line.
