Admin dashboard: three directions

Today the admin page is one long column of cards: application settings, syllabus import, the knowledge index, default images, Google Drive cleanup, Drive files, training calendars, users and the cleanup history. Nothing says what needs attention, and the dance styles and categories pages are not linked at all.

All three directions follow the profile page (#229): a summary panel with counts, then settings rows that show their current value. All three add a "Needs attention" line and rows for dance styles and categories (#386). Every area of today's page is kept. Each direction is shown at desktop width and at 375 px. Counts, names and file sizes are examples.

Applies to whichever direction is chosen

  • Needs attention lists only real conditions: a stale or incomplete knowledge index, unverified users, orphaned Drive files. When nothing needs doing it reads "Nothing needs attention", in a neutral chip.
  • Every action of today's page stays and keeps its current behaviour: save application settings, run the syllabus import, rebuild the index, upload default images, simulate cleanup, run deletion, remove public permissions, add and edit calendars, create, edit, enable and verify users. Destructive actions keep their confirmation.
  • Dance styles and categories (#386) appear as rows that open the existing /dance-types and /dance-categories pages.
  • Admins only. The page and every row stay behind the admin role. Counts come from the services, never from repositories in the controller.
  • Copy: "Knowledge Index (RAG)" becomes "Knowledge index", "Google Drive Maintenance" becomes "Google Drive", and "Application Configuration" becomes "Application settings". All labels go into both message files.
